# 消息能力与限制

消息由 `e.reply(message, quote, extra)`、事件联系人 `sendMsg` 或显式获准的主动发送入口交给适配器。群聊与 C2C 共用规划和回执规则，发送权限按各自场景判断。

## 内容与顺序

- 支持文本、图片、语音、视频、文件、Markdown、键盘和图文卡片元素。不同内容受相应格式、大小和平台权限约束。
- 一次调用按元素顺序发送；两次调用保留各自边界。`makeForwardMsg` 的内容降级为有序普通消息，不伪造原生聊天记录卡片。
- 群图片默认使用同一条消息上方提及、下方图片的排版；C2C 不自动添加群提及。无法取得图片尺寸时可退回普通媒体并返回兼容提醒。
- 本地图片经格式和尺寸检查后上传。Markdown 临时素材按账号管理，只清理能够确认由本适配器创建的对象，不删除未知归属的素材。
- 图片中的操作按钮默认保留；数组和转发节点分别绑定自己的键盘，按顺序发送并返回各段回执。多层回复包装保留第三参数，显式群提及与自动图片提及去重。任意组合仍需满足平台权限、消息长度及回复额度。

## 接收分享卡片

官方事件中的独立分享卡片将完整的 `ark_data` 映射为云崽标准 `{ type: "json", data: "JSON字符串" }` 消息元素，保留提供方扩展字段；也支持以 JSON 字符串承载的卡片。宿主会将该 JSON 纳入 `e.msg`，插件也可直接读取 `e.message`。卡片内业务字段和链接由消费插件解释，适配器不按视频平台或插件名称做特判，不下载封面，也不将标题提取为独立指令文本。

并行消息中的当前作者元素按原顺序接收，完全相同的 JSON 卡片只保留一次；正文已有链接时仍保留 JSON 元素。引用消息只将新回复正文交给指令匹配，不自动解析其历史子元素；聊天记录及其他作者的嵌套内容也不会被当作当前发送者的新指令。处理限制深度、节点数、总长度和附件数；无法解析为对象的卡片被忽略，超过边界的事件拒绝派发。卡片内身份和权限字段不改变外层发送者或主人权限。

独立卡片无需附加提及，但仍需满足下方的群消息接收授权和宿主群配置；平台未推送的消息无法由适配器补收。

## 授权与配置

免提及群消息需要 `receiveGroupMessages=true`、平台及群内接收授权，以及宿主对应群允许非提及消息。QQ 资料页的推送开关不等于接收全部群消息的授权。

`allowProactive` 默认关闭。启用后仍只允许向已观察且通过本地范围检查的联系人发送，平台可以拒绝。禁止借用另一会话的被动回复权限。

原生键盘仅在平台明确拒绝按钮权限时转成可读文字。消息 POST 超时、无效响应或服务端错误表示投递未知时，停止后续发送并保留已有回执，不重发整条消息。

## 回执

全部成功的 `ok` 为 `true`；部分成功返回 `ok=false,status=partial` 并保留已确认消息 ID。`receipt:true` 可以取得零成功段失败的详细结果。完整字段及调用方处理见 [公共接口](PUBLIC-CONTRACTS.md#回执规则)。

## 视频发送

QQ 富媒体接口将超过 30 MB 软限制的视频降级为文件。适配器在通用媒体上传入口处理所有调用方提供的本地文件、Buffer、Uint8Array 和 base64 视频：不超过该限制时保留原文件，超过时先生成 H.264 / AAC、yuv420p、faststart MP4，再以 `file_type=2` 上传。群聊与 C2C、事件回复与联系人发送使用相同规则；显式 `segment.file` 仍表示文件。

大视频处理需要运行环境的 PATH 中存在 FFmpeg（含 libx264、AAC 编码器）与 FFprobe。输出限制为 28,000,000 字节，并保留体积余量；按时长计算码率，分辨率最高横屏 1280×720、竖屏 720×1280，不放大小视频。编码后复核大小、编码与视频时长，不通过截断视频满足大小限制。转换可能降低清晰度并增加等待时间，最多同时执行一个转换任务，任务保留原有回复有效期并受两分钟处理时限约束。

原文件保持不变，临时副本在上传结束或失败后清理。工具缺失、超时或无法完成压缩时返回明确错误，不将原始大视频当作文件发送。输入仍受 `maxMediaBytes` 限制。HTTPS URL 继续由 QQ 平台拉取，适配器不在本地下载或转码远程地址；调用方须提供限制内的可播放 MP4，或将本地视频交给适配器处理。客户端是否显示播放器还受平台内容审核、账号权限及客户端支持影响，上传成功本身不能证明播放验收通过。
