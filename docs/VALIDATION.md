# 验证方法与范围

测试以 Node.js 24.x、固定版本 Miao-Yunzai 源码和隔离网络为基础。宿主来源、提交和文件 SHA256 保存在 [宿主清单](../test/host/manifest.json)，加载前逐项校验。自动化验证不读取实际账号的配置、聊天记录或业务数据库。

## 执行检查

```sh
npm ci --ignore-scripts
npm run fixtures
npm test
npm run test:contracts
npm run test:host
npm run check
```

`npm run fixtures` 将固定提交的公开源文件保存在被忽略的缓存目录。也可执行 `npm run fixtures -- --from-host <源码快照目录>` 导入匹配快照；文件校验要求相同。POSIX 文件权限测试需在 Linux 上运行。

## 覆盖范围

| 层次 | 验证内容 | 边界 |
| --- | --- | --- |
| 配置与锅巴接口 | 默认禁用、输入校验、原子保存、空密钥保留及错误脱敏 | 管理页面与访问代理需要独立验证 |
| API 与网关 | token 缓存、鉴权刷新、心跳、恢复、去重及有界退避 | 模拟网络不能证明实际平台准入或授权 |
| 身份与联系人 | AppID/场景隔离、可信关联、主人授权及账号选择 | 不认证普通 QQ 号所有权，不推断跨场景身份 |
| 分享卡片接收 | 标准 JSON 元素与扩展字段保留、独立卡片免提及、并行顺序、重复卡片去重、宿主匹配与结构消费、引用和身份隔离 | 需由平台推送卡片内容；模拟测试不能证明真实推送或所有业务解析器可识别该结构 |
| 消息与回执 | 顺序、调用边界、部分成功、未知投递停止及撤回 | 组合消息和第三方包装需要持续增加覆盖 |
| 媒体与素材 | 格式、尺寸、上传、缓存和归属明确的清理 | 审核和 QQ 客户端渲染需要实际场景验证 |
| 宿主与业务回归 | 固定 Loader、事件总线、Runtime 及版本受限的插件调用 | 不等于所有云崽分支和所有业务插件兼容 |

测试凭据和标识均为虚构数据。接口模拟服务只使用本机回环地址，不是产品提供的网络服务。测试通过后，仍需在受控场景分别确认平台资格、权限、媒体显示和交互；连接上线不能替代这些验证。
